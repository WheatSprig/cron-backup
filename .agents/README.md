# `.agents/` 本地工作区约定

这个目录是**本地 AI 工作区**，不是产品代码。除本文件外，所有内容都不进版本库。

## 哪些提交，哪些不提交

- `.agents/README.md`：提交，作为工作区规范。
- `.agents/todo.md`：在途任务列表，**不提交**。
- `.agents/plans/`：功能/大目标计划，**不提交**。
- `.agents/scratch/`：可选的过程材料，**不提交**。
- `.agents/notes/`：可复用的环境/排障结论，**不提交**。
- `.agents/archive/`：已完成任务归档，**不提交**。

`.gitignore` 已用 `.agents/*` 忽略全部内容，再白名单放行 `README.md`。
任何时候都不要用 `git add -f` 绕过。

## 在途任务

`todo.md` 只记录当前在途任务。每条任务占一个六行块，字段顺序固定：

```markdown
- 任务：<一句话说清要交付什么>
- 级别：轻量切片 | 功能切片 | 复合大目标
- 分支：<类型>/<slug> | feature/<大目标 slug>
- 计划：.agents/plans/<YYYYMMDD>_<slug>.md | 无（轻量切片）
- 当前单元：<下一步要验收的一件事>
- Blocker：<没有就写“无”>
```

规则：

- 一个在途任务对应一个分支；同一主题的后续修改回原分支，不另开分支。
- 轻量切片可以没有计划文件，但 todo 必须有记录。
- 功能切片 / 复合大目标必须先写计划，再动手。
- 任务完成后删掉对应块；计划移到 `archive/`，在 `ARCHIVE.md` 记一行。
- 不做任务分片机制，不强制 `scratch/`；目录按需创建，不放 `.gitkeep`。

## 计划文件

`plans/<YYYYMMDD>_<slug>.md` 至少包含：

1. 目标与非目标；
2. 已定决策和硬约束；
3. 可验收的实施单元（复选框）；
4. 测试/验收方式；
5. 风险与待确认项。

执行中的临时清单可以放 `scratch/<slug>/`，任务完成后删除。

## 命名

- `<slug>`：小写 ASCII + 连字符，例如 `cron-backup-v2`、`retention-prune`。
- 分支名、计划文件名、scratch 目录名使用同一个 slug。
- 计划里不要写只有对话中才有定义的“第几步”；对外提交信息同样不引用计划编号。

## 恢复现场的顺序

1. 读 `AGENTS.md`；
2. 读 `todo.md`；
3. 读对应计划；
4. 检查分支和 `git status`；
5. 从“当前单元”继续。
